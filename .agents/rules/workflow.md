# Git & Pull Request Workflow Rules

## 1. Branching
- **Never push directly to main.**
- All development and fixes MUST be done in isolated branches and then merged to the `main` branch.

## 2. Commits & Naming
- All commit messages must strictly follow **Semantic Commit Conventions** (e.g., `feat:`, `fix:`, `docs:`, `refactor:`).
- All Pull Request titles must also be semantic.

## 3. Pull Requests
- Each PR description MUST include a detailed paragraph thoroughly explaining the changes, the reasoning behind them, and their impact.
- Ensure appropriate tags and labels are assigned to every PR before review.
